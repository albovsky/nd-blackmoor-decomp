Put scratch/evidence in `work/`; user-facing source, reports, builds and plans in `outputs/blackmoor-decomp/`. Do not publish proprietary executable/resource bytes or generated resource dumps. Keep large tool results on disk and print only bounded summaries.

Track M production method (owner ruling, 2026-10-14; evidence in `outputs/blackmoor-decomp/M0-binary-census-report.md`). Original x86 functions may be reconstructed as tool-assisted assembly: the project-owned generator (packet M03) emits Intel-syntax GNU assembly for one function from the owner's local original, an implementer annotates it (function and label names, frame and field symbols, the Track N source it corresponds to, unverified branches), and an independent reviewer confirms that the annotated source reassembles byte-exactly with the pinned `i686-w64-mingw32-as` 2.43.1 before the function counts. Such functions carry the class `tool_assisted_reconstructed_assembly`, reported separately from `explicit_reconstructed_assembly_source`; neither class claims original C++ or compiler provenance. Permitted encodings are mnemonics plus the `{load}`/`{store}` and `{disp8}`/`{disp32}` prefixes, the `.d8`/`.d32` branch suffixes, and `.insn` only in the five spellings listed in section 5 of the M0 report (16-bit and 32-bit accumulator immediates, the `DC C0` x87 form and `81 /x` word immediates); with those, the census reproduces 100% of the code bytes, so no other byte directive is permitted in code. Owner rulings of 2026-10-14 refine this: (1) jump and switch index tables, and only those, may be written as `.byte` lists in the `.s`, in a data item labeled `IDXTAB_<va>` whose comment names the owning function and the switch jump (`index table of FUN_<va> for the switch jump at 0x<va>`); the auditor enforces the label, and no other byte list is permitted. (2) Annotation requires named symbols for every register-relative displacement, frame (`[ebp±n]`), stack (`[esp+n]`) and object-field (`[reg+n]`); absolute addresses stay numeric. (3) The assembler is pinned by its version line (`GNU assembler (GNU Binutils) 2.43.1`) plus a self-test that reassembles a fixed source and must reproduce the expected bytes exactly, not by the SHA-256 of one machine's binary. Machine-byte arrays, `incbin`, patching the original, and committing original code, data or resource bytes remain forbidden; the image composer (packet M02) may reference not-yet-reconstructed ranges from the local original at build time and must report them as referenced, never as matched. CRT, MFC and Vorbis code is reconstructed the same way and tracked as its own class.

Slice completion requires the packet's exact acceptance checks, pinned executable/code/native hashes, an independent review, and an explicit list of unverified branches. The integrator reruns meaningful combined checks before updating completion status. Do not mark the complete game done until both native gameplay and whole-file x86 matching pass.
