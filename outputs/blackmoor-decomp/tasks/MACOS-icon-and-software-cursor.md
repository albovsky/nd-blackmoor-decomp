# Build icon and software cursor implementation plan

> Execute under the existing AGENTS.md delegation and independent-review workflow; root owns shared build/platform/app integration and publication. No further permission is required for the already-requested merge.

**Goal:** Future native builds carry the owned game icon, the recompiled game does not show the macOS cursor over its framebuffer cursor, and Glib can transfer a self-contained private package to his other Mac.
**Architecture:** Preserve the declared owned GOG Mac app icon byte for byte when available, after checking the owner GAME.EXE hash. Otherwise extract icon group 128/language1033 from the pinned executable at build time; decode its validated 4-bit palette, bottom-up XOR rows and AND transparency mask to RGBA PNG, then use native PNG resizing/ICNS packaging. Verify the source-resolution palette/mask pixels again in the builder before publishing the icon, and name it in Info.plist before signing. Native ICO decoding corrupts this old format, so it is not used. The platform has an opt-in software-cursor mode using an AppKit transparent cursor rectangle limited to the visible rendered surface. The recompiled frontend follows the guest ShowCursor counter through a thread-safe visibility query, so requests for a native cursor remain visible. Other platform clients keep their existing cursor behavior.
**Spec:** User request in the authorizing Codex chat: make the icon part of the build and merge; report/fix overlapping macOS/game cursors. AGENTS.md and PROJECT-SPEC.md constrain original data and testing.

## Task 1: Icon extractor and integration

- Worker owns only new recomp/build_game_icon.py and tests/test_macos_game_icon.py in an isolated worktree. Root alone edits recomp/build_macos.sh and related shared packaging checks.
- Preserve the established Desktop branding when the immutable owner record identifies an installed GOG Mac app: read its CFBundleIconFile, validate the bounded ICNS and native decode, then publish an exact atomic copy. Check the original EXE hash first. Optional --owner-record is absent-safe; standalone builds keep the pinned-EXE fallback. A present invalid declared icon fails clearly. No icon bytes or owner record are committed or modified.
- Read the Windows RT_GROUP_ICON/RT_ICON resources from the pinned original; decode the strict 16px/32px 4bpp DIB payloads to RGBA PNG with standard-library code and use native PNG resizing/ICNS packaging to create a full multi-resolution ICNS. Preserve palette colors, high/low nibble order, bottom-up rows and AND-mask transparency. No native ICO decoder, wrapper app installation or internet is required. Existing pinned pefile is available. Fail clearly if resource/hash/conversion is invalid; do not silently ship an iconless bundle.
- Write meaningful synthetic parsing/error tests and an opt-in/conditional owner-original conversion check. Observe red then green. Keep generated bytes in private scratch. Return exact inputs, checks and hashes plus a build integration proposal.
- Root invokes extraction into the staged app and sets CFBundleIconFile before signing, verifies strict signature, ICNS decode and original-source hashes on a real build. Independently compare the shipped 16px/32px pixels with the original palette/mask, so a blank, opaque or incorrectly decoded icon cannot pass on dimensions alone.
- The builder must itself check every decoded 16px/32px alpha and visible RGB sample against the validated DIB before atomic publication. A correct-sized but corrupt native PNG, unsupported PNG encoding, checksum/filter/length/decompression failure or pixel mismatch must fail clearly and preserve an existing icon. Keep the native-PNG reader bounded to the two small source representations. Retain the independent test-only pixel oracle; do not mask failing edge pixels in the production gate.

## Task 2: Cursor integration

- Root owns src/macos_platform.h, src/macos_platform.mm, recomp/macos_recomp.mm, recomp/rc_platform.h, recomp/rc_win32.c and bounded cursor fixture/test wrappers.
- Add an opt-in platform API. The recompiled frontend enables suppression when the guest Win32 ShowCursor counter is negative, and disables it when the guest requests a native cursor (counter nonnegative). Expose the existing counter predicate through a thread-safe host query, preserving ShowCursor return values. Synchronize the main-thread policy on ticks. Keep the system cursor visible until a frame is present. Register a transparent NSCursor only for intersection(rendered surface, visibleRect). Do not use global macOS hide/unhide counters. Let AppKit own enter/exit and focus handling.
- Invalidate cursor rectangles when opt-in state, first frame, fit/stretch mode or relevant geometry changes, and on stop/close. Preserve bars/title/menu/outside-app cursor behavior.
- Add a hidden synthetic fixture that observes actual cursor rectangle registration and transparent image pixels without setting/hiding the real pointer, moving the mouse, making windows key/visible or changing owner preferences. Verify default/off, enabled-before-frame, fit/wide/narrow/stretch, clipping, resize/mode update and stop. Observe baseline red and candidate green.
- Add finite actual Win32 ShowCursor return/predicate tests and a no-window frontend-tick fixture which supplies visible/hidden guest requests and records the platform suppression values. Both visible-to-hidden and hidden-to-visible transitions must be covered without original assets, real GUI/audio, or persistent preferences.
