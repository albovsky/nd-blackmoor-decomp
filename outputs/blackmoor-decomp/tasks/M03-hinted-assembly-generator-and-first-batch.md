## Outcome

A project-owned generator turns any indexed original function into annotated-ready Intel-syntax GNU assembly that reassembles byte-exactly with the pinned `i686-w64-mingw32-as` 2.43.1, an auditor enforces the annotation and review contract, and a first batch of functions is produced, annotated, independently reviewed and classified `tool_assisted_reconstructed_assembly`.

## Ownership

Own only new files: `outputs/blackmoor-decomp/scripts/gen_hinted_asm.py`, `outputs/blackmoor-decomp/scripts/audit_tool_assisted.py`, `outputs/blackmoor-decomp/asm/` (one `.s` per function plus a batch manifest `asm/batch-001.json`), `outputs/blackmoor-decomp/tests/test_gen_hinted_asm.py`, `outputs/blackmoor-decomp/tests/test_audit_tool_assisted.py`, and private `work/analysis/slices/M03.*`. The function index, existing matching sources, verifier, engine and app files are read-only. The generator reads the owner's local `GAME.EXE` and `llvm-objdump`; its census output over all functions stays private under `work/`. Committed `.s` files contain mnemonics, labels, symbols and comments only; never raw byte lists except `.insn` operands for the four permitted residual classes.

## Generator contract

- Input: one or more function VAs from `function-index.json`. The distance to the next indexed start is a span, not a proven function end: it can hold the function's switch tables, byte index tables and `int 3` padding. The generator must split every span into the function's code (from the entry through its last reachable instruction, verified by following the function's own control flow, not by linear sweep), its switch and index tables, and its trailing padding. Only the code part is the function; tables and padding are data items the generator emits with their own labels and hands to the M02 composer's description, so that no byte is counted twice between M02 and M03. The auditor rejects a function whose span split is missing or whose code part does not end at a terminal `ret`, `jmp` or tail into data.
- Output per function: `.intel_syntax noprefix`, `.code32`, the function placed at its original section offset (`.org <va> - 0x401000` inside `.text`, so every relative displacement resolves at assembly time), a global symbol `FUN_<va>`, local labels at every branch target inside the function, every call or jump target outside the function defined as a section-relative symbol at its original offset (`.set FUN_<target>, .text + (<va> - 0x401000)`), so the object carries no relocations and `verify_matches.py` can compare the symbol's bytes directly (a bare numeric target or an absolute `.set` leaves a PC-relative relocation in COFF; tested against the pinned assembler), and encoding hints derived from the original bytes: `{load}`/`{store}` for register-register forms, `.d8`/`.d32` branch suffixes, `{disp8}`/`{disp32}` displacement sizes, and `.insn` only in the five spellings of the M0 report, section 5: `.insn 0x66, 0x05, imm{:u16}` and its `0x0d`/`0x25`/`0x2d`/`0x3d` siblings, `.insn 0x05, imm{:u32}`, `.insn 0xdc, 0xc0`, and `.insn 0x6681/<digit>, <dword ptr memory or 32-bit register name>, imm{:s16}`; `xchg` operand order uses `{load}`. Trailing `int 3` padding and any switch table are emitted as data items with their own labels.
- Header comment: VA, extent, SHA-256 of the original extent (hash only), the evidence id from `function-index.json`, the code region (game, Vorbis, CRT/MFC), and empty fields the annotator must fill: function name, argument and local symbols (`.equ` for every `[ebp±n]` offset used), fields touched (`this+n`), callees by name, the Track N module and symbol the function corresponds to or `host-adapter: none`, and unverified branches.
- Census mode: run the generator over all 4,188 functions and reassemble; report bytes exact per region and list any instruction the generator cannot express. The M0 census reproduced 100.000% of the 1,205,254 bytes it treated as instructions with these spellings, but that figure is a round-trip measure, not a code census: it counts `int 3` padding (assembled as `int3`) and roughly a thousand table bytes that the linear disassembler rendered as valid instructions, and its only failures were four invalid-opcode byte runs that are table data. This packet's gate is therefore not that number. The generator derives the code total from its own span split (`.text` size 1,213,018 minus the finalized table, index-table and padding bytes; the M0 estimate is about 1,202,000) and must reassemble 100% of that code total exactly, listing each exception.

## Audit and review contract

`audit_tool_assisted.py` accepts a batch manifest and, for each function: reassembles the committed `.s` with the pinned assembler, rejects any object that carries a relocation, compares the symbol's bytes to the original code part (through `verify_matches.py` semantics) and the emitted data items to the original table and padding bytes separately, rejects raw byte lists outside permitted `.insn` forms, rejects missing or placeholder annotation fields, requires every `[ebp±n]` offset to be named, requires at least one comment per basic block, records source, object, assembler and original-extent hashes, and writes the report. Independent review (the `slice-reviewer` subagent) then checks that the names and comments describe what the bytes do, not what the pseudocode guesses, and that the Track N cross-reference is real. A function enters the `tool_assisted_reconstructed_assembly` class only after the audit passes and root accepts the review.

## First batch

Batch 001 is every function for which the project already holds reviewed Track N source or an accepted recovery report: the CIF decompressor, the dependency reducer, the boot initialization routines, the A-37 constructor, the S08-2/3/4 families (as a cross-check against the hand-written sources, which stay in their own class), the HIS audio decode and PCM quantization kernels, and the sound-control functions named in `action-sound-recovery.md`. Take addresses from `function-index.json` and the recovery reports; do not guess extents. Report batch code bytes by region, the data items handed to M02, and the delta against the 398-byte baseline without double counting.

## Steps

- [ ] Generator, census mode over all functions, exceptions list.
- [ ] Auditor with mutant tests: a wrong hint, a dropped label, a raw `.byte` run, an unnamed frame offset, a stale hash, an object assembled with Xcode's assembler, an object with a relocation, a span whose table bytes were counted as code.
- [ ] Batch 001 generated, annotated, audited; request independent review; repair findings.
- [ ] Hand off: commands, census and batch reports, hashes, the list of functions that failed review and why.
