## The kernels (written by the owner thread; do not edit, report disagreements with a concrete counterexample)

Read the header comments: they carry the original addresses, field offsets and host contracts.

* `src/action_family_9a_runtime.[ch]` raw 0x9a (27-byte body, decoder `action_family_9a.c`). Dispatcher arm `0x429d34` gate mode 0 -> `0x4336ad(row, 0)`. Phase 0 -> 2 (pending); phase 2 stops the sound channel(s), optionally takes the 0x0a-style scene change cells and the event flag store, then completes directly; other phases nothing. Host: `stop_channel` (0x4fc878 on `0x5c3a67`), `event_flag_invalid`, `store_event_flag`. Native-only refusal: invalid event flag index (before any effect).
* `src/action_family_6d_runtime.[ch]` raw 0x6d (1-byte body, decoder `action_family_6d.c`). Arm `0x4290c0` gate mode 0. Selects a popup teardown from the cells `[0x5bb22a]`, `[0x583204]` (host `teardown`), unloads the scene sound (`0x4fb018`, host `unload_scene_sound`), stores the outer-state cells and completes directly (DIRECT_COMPLETED, phase untouched). Native app has no popup screens, so its cells stay 0 and only the tail runs; a visit that needs a teardown without a host `teardown` is refused (UNSUPPORTED).
* `src/action_family_1c_runtime.[ch]` raw 0x1c (105-byte body, decoder `action_family_1c.c`). Arm `0x427cc3` gate mode 1 (already in `scene_conditions_gate_mode_for_type`) -> `0x4cb586(row)` on the singleton `0x63847b` (CInteractiveVideo). `c1c_visit` is the whole handler including the ".IV" file loader `0x4cbba9`; `c1c_render` is the z entry callback `0x4cc79a`. Phase 0 waits for the movie player `0x637fcf` (state 2 and a matching clip name), phase 1 follows the player's hotspot index, phase 2 frees and completes (COMPLETED = generic completion `0x42ba3a`). Host: player getters, the file (open/read/close), z entry alloc/register/release, the word cell `[0x583a29]`.
