## What changed in the method

1. **Data-flow proofs for dropped instructions** (`scripts/fl43_equiv.py`, used by `scripts/fl41_survivors.py`): on the CFG of the original instructions, a dropped instruction is a no-op when (repeat) the same load already ran, or the register was stored to that slot, on every path with no intervening change of its inputs (a call or a store through another pointer ends memory facts; a call ends eax/ecx/edx facts), or (dead) every register and flag it writes is overwritten before it is read. Both need a frame whose address is never taken (`lea` of ebp/esp, ebp/esp copied) and a plain `push ebp; mov ebp, esp` prologue; otherwise no proof. Stated assumption (the same one `same value` already made): the caller's pushed arguments are not aliased by a callee's other pointers, and pushes land below the named slots. Guard test `tests/test_fl43_equiv.py` requires that no proof exists for an instruction whose dropped mutant was killed in the committed log. 224 of the 447 unexplained survivors of the held rows were explained this way.
2. **Extended mutants** (`--extended`): every literal of a statement (not only the first), every memory access of a statement, `and/or/xor` swaps of logic blocks, and the neighbouring jump condition (signed/unsigned, strict/or-equal). Survivors now carry the hash of the mutated line so that a (kind, line) with several mutants is judged mutant by mutant (`scripts/fl41_o2_classify.py --extended`).
3. **Kills count only on seeds where the unmutated port agrees with the original** (`agrees()` in the check; seeds where it does not are printed as `divergent seeds`). FL-41's check also counted such seeds. Two causes, both in the world model, not in the ports: a callee stub wrote into the code of the function under test (the original then ran the changed bytes), and reads of the stub-entry or stop page returned page-fill data natively but nops in the original. `tests/fl41_world.py` now closes both (`FL43_WORLD_FIXED`, default on; `=0` restores the old model; the recorded corpus runs and the oracle digests are identical in both). `tests/fl43_wide_check.py` runs extra seeds (28 rows x 300: no difference).
4. **Alarm bug fixed**: one `signal.alarm(20)` covered the whole seed list a mutant ran against; a list longer than 20 s killed the child and the parent recorded a kill. Hardening lists (600 seeds) and slow rows were affected. The alarm is now per scenario and hangs/crashes are listed (`mutants killed by a hang or crash`). **`tests/fl40_mutation_check.py` has the same bug** (reported to the coordinator): FL-40/FL-42 credits below 0x480000 were not rechecked under the fix.
5. `scripts/fl43_directed.py`: directed hardening (memory cells a compare reads set to the other operand, +-1, its negation, values with a high half). It killed 2 of 17 leftover survivors in six near-miss rows and rescued none.
6. `scripts/fl43_prune.py` keeps only the rows that pass; the rest go to `tests/fl41_pending.json`.
