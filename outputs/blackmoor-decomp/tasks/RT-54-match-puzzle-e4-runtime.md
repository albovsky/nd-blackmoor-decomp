# RT-54: raw 0xe4 Match Puzzle runtime

Owner thread: Claude Sonnet (cloud). Follows RT-51 (PR 117). Ranking from `scene-action-coverage.json` after PR 117: 0x1c, 0xd3, 0xe4, 0xeb and 0xf5 each unblock two scenes (0xd3 is RT-53's). 0xe4 (resources 2295 and 2296, one row each) is the mouse-only one of the rest: 0xeb (Multibuild) needs right-button rotation like 0xea and 0xf5 (Typing Quiz) needs keyboard input, neither of which the app has; 0x1c reads files and drives an external player. Raw 0xe4 is the "Match Puzzle" (JAN_GlyphMatchPUZ): a board of glyph pieces (the real rows: 5 rows by 7 columns, 26 kinds), a score, a countdown (61 s and 41 s) and a target score (2,500 and 5,000). The player picks a piece and then a second one; the two swap; every run of three or more equal pieces in a row or column is marked, scores and is refilled; reaching the target wins (scene block 1299), the exit button leaves (block 1298).

Contract: `src/action_family_e4_runtime.h` (written first by the owner thread, from the disassembly); the kernel `src/action_family_e4_runtime.c` is the owner thread's. GAME.EXE SHA-256 afd337a2...5c45; private evidence is `work/original/GAME.EXE` (extracted from `/mnt/project-files/private-inputs/work-private.tar.gz`, already in place in the owner's container); disassembly helper `work/rt54/pe.py` (`python3 pe.py <hex va> <len>`), Ghidra pseudocode of every function `python3 work/rt54/pseudo.py <hex va>...`, the two real 2034-byte bodies `work/rt54/body_2295.bin`, `work/rt54/body_2296.bin` (also at offset 282 of `work/analysis/hiff-resources/2295.bin` and 204 of `2296.bin`; locate by the name "JAN_GlyphMatchPUZ_OVL"). Engine hooks used by the code (outside this slice; replace them in the oracle and implement them in the native host, in the original order): `0x4c2790` load image (thiscall ECX 0x5cf659, `ret 0x10`: "CIFTREE" 0x54c8d0 / 0x54c8e8, name, 6, label); `0x4c2dfb` release (ret 4, zeroes the cell); `0x4d39f9` alloc generic Z slot; `0x4d3992` release slot (cdecl, one word); `0x4fb77a` / `0x4fba69` sound prepare / stop (ECX 0x5c3a67, ret 4, pointer to the record); `0x4fb2e3` play (ret 4, channel word); `0x4f6334` busy (ECX 0x5cf1eb, ret 4); `GetTickCount` ([0x52a23c]); `0x50cd50` rand (CRT; scripted values); `0x4e8d96` commits the pending inventory item (called stop_ambient in the kernel by mistake); `0x4c924d` / `0x4c92c5` font image acquire / release; `0x4d2c20` text draw; `0x4d3836` text measure; `0x4c5377` blit (thiscall ECX 0x5cf659, `ret 0x14`: source surface, target [0x5cf665], source rect pointer, destination rect pointer, label); `0x50ca3e` sprintf (formats "%lu", "%2dm %2ds", "%s"); `0x42ba3a` generic completion (original code runs).

Handler phases (row phase dword `0x5bb632 + row * 0x8d`): phase 0 = init (row, active, start flag, ambient stop, fill, slot, surfaces, sound prepare A/B/C, counters, score/time/target text, phase 1); phase 1 = switch on obj+0x2c (jump table `0x4778b3`, states 0..6, above 6 nothing, see the header for the meaning); phase 2 = finish (start flag, stop A/B/C, scene block win or exit, font release, `0x42ba3a(row word)`, cleanup). The kernel header and source carry every detail; where this packet and the disassembly disagree the disassembly wins and the packet gets fixed.

Native-only refusals (the oracle must not run them against the original; test them natively): body validation (`e4r_validate_body`), phase 1/2 without phase 0 for the row, board indexes or piece kinds outside the board, event flag index outside the host window in phase 2.

Known wrinkles to preserve: the vertical-run branch of CheckForMatch tests the HORIZONTAL run length for the 3-run time bonus; a swap needs no adjacency; the second piece is only checked on a later visit (obj+0x8d9) and only if the first check did not start the refill; the time-left text and the end test use unsigned tick arithmetic; the font reference count only ever grows in the original (every text draw acquires, the finish releases once); the fill draws kinds 0..kinds-2 and divides by kinds-1.
