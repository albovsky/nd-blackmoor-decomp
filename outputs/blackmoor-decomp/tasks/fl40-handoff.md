Cloud thread, 2026-10-22 PDT. GAME.EXE SHA-256 `afd337a2468e0cd540f487db2c121ccb9ccb9757836578c15d2d8a52f3485c45` (read only). Ledger: 1,744 (main after PR 164) -> **1,854 ported** (+110).

## What was built

- `scripts/lift_function.py`: a one-to-one static translator of a function's x86 instructions to C over a virtual 32-bit address space (memory reads/writes and callee playing go through a host; flags follow the unit the tests run the original on, QEMU/Unicorn semantics for the undefined ones). It refuses x87, register-indirect calls, jump tables that leave the body, self-recursion and callees whose stack discipline it cannot read from their own `ret N`. `--census` says what lifts.
- `scripts/fl40_generate.py`: seed search (coverage-guided with compare-feedback mutation) on the ORIGINAL bytes under Unicorn until every instruction runs and both directions of every conditional jump are taken; writes `src/original_methods_fl40.c`, `tests/fl40_corpus.json`, `tests/test_fl40_differential.py`. A row whose seeds cannot cover the function is not written (listed below).
- `tests/fl40_world.py`: the shared deterministic world (lazy pages, recording stubs for callees, Win32 imports by stdcall arg count). Equality is checked on final registers, the ordered write trace and the ordered stub-call log, which now records eax, ecx, edx, ebx, esi, edi, ebp as the call sees them.
- `tests/fl40_original_oracle.py`: original bytes only; exit 0 only if every instruction of every row runs and both jump directions are taken (262 rows). `tests/test_fl40_differential.py`: translation vs original on every seed.
- `tests/fl40_mutation_check.py` + `tests/fl40_equiv_check.py` + `scripts/fl40_survivors.py`: mutants of the generated C (flipped jumps, changed literals, add/sub and shift swaps, operand swaps, wider/narrower memory access, dropped statements, wrong registers) must be killed by the corpus, then by 40 extra seeds, then by 300 + 300 hardening seeds (the second range uses a style whose values have a small low half and nonzero upper bytes). A survivor counts as explained only if (a) `cc -O2` gives identical assembly for the mutant and the translation, or (b) it is a reload of a frame slot that the register already holds (straight line, no call, no store that can hit the slot), or (c) a frame/esp adjustment that every return path undoes. Everything else holds the row back.
- `scripts/fl40_accept.py` writes the acceptances (class `native_oracle_verified`, note starts "Machine-translated", so one owner ruling can drop the batch); `tasks/fl40-blockers.json` holds the written reasons for the 11 rows that had old slice blockers.

## Things the owner may care about

- These rows are machine translations of the instructions, not recovered source. If you rule they do not count, the batch can be dropped by removing the `native_oracle_verified` entries whose note starts "Machine-translated from the original instructions (scripts/lift_function.py)" in `function-ledger-overrides.json`.
- Callee behaviour is a recording stub; the number of bytes a callee pops comes from the callee's own `ret N`, used by both the stub and the translation, so an error there would be shared. Callees are assumed to preserve ebx, esi, edi, ebp; their flags are not modelled.
- Some undefined flags (after `imul`, `mul`, shifts by more than one) follow Unicorn, not hardware; no accepted branch consumes one directly.
- Rationale for the cleared old blockers (11 rows) is in `tasks/fl40-blockers.json`; the reviewer found two of them overstated and they were rewritten (`0x4264e8` and `0x44a2b7` are straight-line helpers; the old item concerns their callers).
- Names: the new ports replaced inferred names; `function_names.py write`, `annotate_machine.py annotate`, `--named`, `--derived --named`, `refresh` and a re-audit of all ten batches were rerun (10 of 10 accepted, pinned binutils 2.43.1 rebuilt in this container from the Ubuntu old-releases orig tarball with `bootstrap_matching_s08_2_gas.sh`).
