# RT-24: raw 0xd9 Mouselight puzzle runtime

Owner thread: Claude Sonnet (cloud). Follows RT-23 (`tasks/RT-23-conversation-3f-runtime.md`): 0xd9 is the second most-used missing action type (245 scenes, 274 records; ranking in `scene-action-coverage.json`).

## The original (GAME.EXE, SHA-256 afd337a2...5c45)

Recovered by this slice (pseudocode is navigation; every number below was checked in the x86):

* Dispatcher `0x427a50` arm `0xd9` at `0x42a383`: gate `0x423f57(deps, 0)` then `0x47d788(ECX = 0x6246dc, row)`. The object at `0x6246dc` is a static singleton.
* Typed body `0x23` bytes, copied by the loader `0x47d682` (called from the scene loader `0x40b34a` with ECX = 0x6246dc but `this` unused): `+0x00` NUL-terminated name of a CIFTREE image, `+0x21` radius byte, `+0x22` mode byte. Corpus (274 records in 245 scenes): radius 150 (mode 1) in 261, 200 (mode 1) in 10, 100 (mode 1) in 1, 50 (mode 0) in 2; 26 scenes carry more than one row.
* `0x47d788` is a phase switch on the row phase dword (`0x5bb632 + row*0x8d`): **phase 0** sets `+0x57 := 1`, `[0x5bb1ca] := 1`, `+0x1d := row`, `+0x1c := 1`, `+0x55 := radius`, the window `+0x29/+0x2d/+0x31/+0x35 := 0`, allocates `+0x49` (16 r^2 bytes, never used again), then mode 0: `+0x51` mask (4 r^2 bytes) with 1 where `sqrt(dx^2+dy^2) < r` for dx, dy in -r..r-1 (index `(r+dy)*2r + (r+dx)`), else mode != 0: `+0x4d` alpha map (4 r^2 floats, zeroed) with `exp(-(float)(d2*d2) / (float)(r^4/2))` (int32 wrap, `r^4/2` truncated toward zero, division in double, result stored as float) where `sqrt(d2) < r`, else 0; then `0x4d39f9` (first free generic Z entry 0x18..0x3f, stride 0x4a at 0x5d1591), stores type 10, callback `0x47df57`, surface `+0x1f`, flags 0,0,1,1, word 0 and the label "MOUSELIGHT PUZZLE BITMAP" into it, loads the image through `0x4c2790("CIFTREE", name, 6, "DF_MouselightPuzzle_Surface")` only if `+0x1f == 0`, stores the surface into the entry again, row phase := 1. **Phase 1** copies the window to `+0x39/+0x3d/+0x41/+0x45`, then if `(int16)+0x27 > [0x583192] - [0x58318a] + 5` zeroes the window, else clamps `+0x29 = max(x-r,0)`, `+0x31 = min(x+r-1, [0x5831ae])` (floor 0), `+0x2d = max(y-r,0)`, `+0x35 = min(y+r-1, [0x5831b2])` (floor 0) with x = int16 `+0x25`, y = int16 `+0x27`. There is no phase 2: the row never completes.
* `0x47d734(x, y)` (called by the pointer cascade `0x4f0059` at `0x4f0fdc`, x = `[ptr+0x5e]`, y = `[ptr+0x5a]`, both view-relative hot-spot coordinates): stores `+0x25`, `+0x27` as words when `+0x57 != 0`; returns 0. `0x47d640`: `slot entry +0x14 := 1` when `+0x57 != 0` and `+0x23 != -1` (called from `0x43d7f0`). `0x47d59b` (scene clear `0x4381f4`, `0x43dbe3`): `0x4c2dfb(&+0x1f)`, frees `+0x49/+0x4d/+0x51`, `0x4d3992(+0x23)` when not -1, then `0x47d4f7` (resets +0x1d,+0x23 to -1, +0x25/+0x27 to 0xfe0c, +0x57 to 0, the windows and the three pointers to 0; it does NOT touch +0x1c, +0x1f, +0x55).
* The render callback `0x47df57` (type 10 entry, called every frame while the entry exists): when `+0x1c != 0` it restores the previous window with `0x4c5377` (opaque copy from the saved scene frame `[0x5d15e3]` to the back buffer `[0x5cf665]`, source rectangle = previous window, destination = the window plus the view origin `[0x583186]/[0x58318a]`) and then blits the current window: mode 0 `0x4c6929` (copy the puzzle image pixels where the mask byte is nonzero), mode != 0 `0x4c62f0` (per channel `bg + trunc((puzzle - bg) * alpha)`, 16-bit wrap). The mask/alpha rectangle is `{0 or (2r - width) when the window is clipped at the left edge, 0 or (2r - height) when clipped at the top, 2r-1, 2r-1}`.
