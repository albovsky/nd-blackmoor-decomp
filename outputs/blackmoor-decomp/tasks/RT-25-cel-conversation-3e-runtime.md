# RT-25: raw 0x3e cel-video conversation runtime

Owner thread: Claude Sonnet (cloud). Follows RT-23 (`tasks/RT-23-conversation-3f-runtime.md`, raw 0x3f) and RT-24. Raw 0x3e is the next most-used missing action type in `scene-action-coverage.json`: 173 scenes, 202 records (170 scenes where it is the only missing type). It runs through the SAME handler `0x420c17` as raw 0x3f; the dispatcher arm `0x427a50` (runtime types 0x39, 0x3a, 0x3b, 0x3c, 0x3e, 0x3f) selects the cel-video arms (types 0x39/0x3b/0x3e) instead of the sound arms.

## The original (GAME.EXE, SHA-256 afd337a2...5c45)

Pseudocode is navigation; every number was checked in the x86. Manager = the conversation manager at `0x6177e8` (ECX of `0x420c17`); offsets below are manager offsets.

* Object image: the constructor model `src/action_family_3e.[ch]` (A-3E.1, original-verified). Raw 0x3e uses the same 0x7a5-byte image layout as 0x3f except the sound descriptor sits at `+0x13a` (channel word at `+0x15b` = 12) and `+0x00` is the 33-byte NAME of a CIFTREE cel header file; `+0x21`/`+0x42` name the layer image files; `+0xa5` byte table (1,2,3), `+0xa8` first frame (0), `+0xaa` last frame (body word), `+0xac` percent words (1,2,3), `+0xb2` layer draw order (1,0,2,3), `+0xb6` layer modes (1), `+0xba`/`+0xfa` rectangle tables (zero).
* Phase 0 (`0x420c17`, after the part shared with the sound arm) for types 0x39/0x3b/0x3e: `+0x6aa := object+0x13a`, `0x4fb77a(descriptor)` (load only, NO play), display name `+0x75d`, cache slots `+0x696 := ftol((float)(last-first+1) * ((float)pct/100.0))` if the s16 at object `+0xac` is positive (x87 `fld/fdiv qword [0x52c680]=100.0/fmulp`; `__ftol` 0x50ce04; stored as a word), clamped to 4..0x4b, `0x418e52("CIFTREE", object+0, &size)` -> header block (`+0xfa5`), 0x2a bytes copied to `+0xf77` (layer count s16 at header+0x24 = `+0xf9b`, sync param dword at header+0x26 = `+0x69e`), names table `+0xfa1 = block+0x2a`, `+0x6a4 := last`, `+0x6a2 := first`, `+0x6a6 := object+0xa5`, per layer `0x41a216(object+0x21+layer*0x21)` -> `+0xfb5+layer*2` (-1 is fatal), reader thread: `0x51dc43(0x46)` then `0x4497a0(0x422e4a, &0x63888b, prio, 4)` (suspended) -> `+0x6b2`; `+0x782 := +0x77e := 0xfff6`, `+0x69c := +0x6a2`, `+0x692 := +0x69c`, `+0x6b6 := 1`, `+0x784 := 0`, `0x449bff()` (resume), row phase := 1. The shared part of phase 0 (earlier) also: tears down an existing reader (`+0x6b2 != 0`: lock `+0x698` := 2, `0x449a94`, virtual delete, lock := 0), initialises the saved layer rectangles `+0x6da`/`+0x71a` ({0,0,1,1} and the same plus the view origin `[0x583186]`/`[0x58318a]`), clears `+0x78a`, `+0x788`, `+0x78c`, sets `+0x690 := -1`, `+0x696 := 0`, and runs `0x41de29` (cache reset).
* Frame cache (75 slots of 0x16 bytes at `+0x1c`: frame word, unused pointer `+0x1e`, four header-object pointers at `+0x22`): `0x41e1e4(frame)` find slot, `0x41e043` first free, `0x41e250(slot)` evict, `0x41dfd2` eviction pass (frames below `+0x69c`, not the current slot `+0x690`), `0x41e0b4(slot, frame)` load (calls `0x417b04(tree_index, block+0x2a+frame*0x8c+layer*0x21, header)` per layer; the header object is filled with data pointer at +0x00, rectangles at +0x35 and +0x45, a word at +0x2f).
* Reader thread loop `0x422e4a` (one pass): lock `0x44c479(&0x617e80)` (spin while 1; returns 2 when closing), `0x41dfd2`, then if `+0x68e < +0x696` and `+0x692 <= +0x6a4`: find slot of frame `+0x692`; when absent take the first free slot (none: skip the advance) and load it; advance `+0x692 += (u16)byte[+0x6a6 + (s16)+0x786] + (s16)+0x78c` (16-bit wrap), or jump to `+0x694` when it is not -1 (then -1); clamp to `+0x6a4`; unlock; `Sleep(1)`. `+0x786` and `[0x5b028e]` are never written (BSS: 0).
* Running (`0x420c17` phase 1, `+0x6b6`): state 1 waits until `(+0x68e == +0x696 || +0x6a4 <= +0x68e)` and the slot of frame `+0x69c` exists, then `+0x690 := slot`, `0x422970` (`+0x782 := +0x69c`, `+0x784 := 1` when `+0x6a4 <= +0x782`), `0x4f6cdc(0xc, (u16)(last-first+1), +0x69e)` (sound with frame sync; 0 return is fatal), state 4. State 4: `[0x5bb1ca] := 1`; ends (state 5) when `+0x77e == +0x6a4` (or Fast Convo `[0x58322a]`, same response-list rules as the sound arm); otherwise frame choice: `0x4f6ef4(0xc)` (monotonic clamp against channel state +0x182 and +0x17a-1; -1 when not playing or the position cannot be read) -> `+0x69c` (-1 or above `+0x6a4` becomes `+0x6a4`), slot lookup; missing frame: `+0x788++` ... `+0x78c` boost (5 max) and `+0x694 := min(+0x69c + +0x78c, +0x6a4)`; found: `+0x78a`/`+0x78c` relax, `+0x690 := slot`, `0x422970`; finally `0x4229b5` (`+0x77e := +0x782`, entry flag `[0x5d191d] := 1` when they differ). States 5/6 as the sound arm but the first sound is stopped through the descriptor at `+0x6aa`.
* Phase 2 (finish) additionally: reader teardown, `0x41de29`, header block free (`0x51dc6c`, `+0xfa5 := 0`), `+0xf77` zeroed, `+0xfa9 := 0`; the rest as 0x3f.
* Render callback `0x422a0a` (Z entry type 0xb, installed by `0x41e33b`, runs when the entry flag `[0x5d191d]` is set): per layer in object draw order, blit lists (restore `0x4c5377`, colour keyed `0x4c609b`, opaque `0x4c5770`), see `convo3f_cel_render` in `src/action_family_3f_runtime.c`.
