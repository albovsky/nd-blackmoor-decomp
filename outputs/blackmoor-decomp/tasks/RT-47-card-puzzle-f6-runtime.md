# RT-47: raw 0xf6 card puzzle runtime

Owner thread: Claude Sonnet (cloud). Follows RT-46 (PR 109) and RT-35 (raw 0xd1, PR 98), whose pattern it copies. Raw 0xf6 (6 rows in 3 scenes: the 10 x 3 two-player card game of the Betty puzzle, resources 1736 and 1738, and the Skull Bones puzzle, resource 2300) is the only type without a handler in those 3 scenes (`scene-action-coverage.json`). The handler `0x45f0e6` is 2,387 asm lines with 16 helper functions; one slice, even though it is large.

## The original (GAME.EXE, SHA-256 afd337a2...5c45)

Recovered from the disassembly (`llvm-objdump -d -M intel`, full listing in the container at `work/f6/all.asm`); the object map, the body layout and the function roles are the comment at the top of `src/action_family_f6_runtime.h` and the offset comments of `F6Object`.

* Loader arm `0x4109f8` (A-F6.1, `src/action_family_f6.[ch]`): 4,934-byte typed body, then the generic 16-byte dependency records. Dispatcher arm `0x42a92b` of `0x427a50`: gate `0x423f57(deps, 0)`, then `0x45f0e6(ECX = 0x61f4b1, row)`.
* Handler `0x45f0e6`: phase 0 (`0x45f123`) init, phase 1 (`0x45f61b`) state machine on obj+0x39e (switch value state - 1, cases 0..0xb; any other state does nothing), phase 2 (`0x460be3`) finish.
* Helpers (all thiscall on 0x61f4b1 unless noted): `0x45de8a` deal / no-card step (2 x `_rand`), `0x45e1ca` pointer hit test (`ret 8`), `0x45e4d4` cursor writer, `0x45e587` click, `0x45e67d` real-sound test (cdecl-like, 1 arg), `0x45e6bd` pick and play a line (`ret 0xc`), `0x45e906` move a card, `0x45e9db` find a card, `0x45ea4a` / `0x45eadc` refill checks, `0x45eb76` computer column pick, `0x45ed60` / `0x45ef5a` start a card slide, `0x45dd4d` cleanup, `0x45dd96` invalidate, `0x45dc8a` reset, `0x460f26` render callback (Z entry type 10; no arguments).
* External calls (host ops of `F6Host`, one per original call, in the original order): `0x4e8d96` (ECX 0x571442), `0x4d39f9`, `0x4c2790`, `0x4c2dfb`, `0x4d3992` (the d1 oracle already hooks these), `0x4fb77a` / `0x4fb2e3` (ECX 0x5c3a67), `0x4f6334` (ECX 0x5cf1eb), GetTickCount, `_rand` `0x50cd50` (new), `0x423259` (ECX 0x619a6b, returns a char pointer or 0; new) and `0x448d11` (ECX 0x619a05, 4 stack args, `ret 0x10`; new), `0x42ba3a`. Render only: `0x4d3a52` (pure, original), `0x4c5377` / `0x4c5d4b` (blits, replace with recorders).
* Original defects the native code must NOT reproduce (tag as expected differences): the 204-byte stack buffer of `0x45e6bd` overflows for a caption longer than 200 characters (keep oracle texts <= 200); division by zero for columns or rows 0; the `_rand` pick loops of `0x45de8a`, `0x45e6bd` and `0x45eb76` can hang (native `F6_ERR_STUCK` after `F6_PICK_LIMIT` draws).
* Original quirks the native code MUST reproduce: the byte compare against -1 at `0x45df28` is never true (unsigned byte); the signed `idiv` of `_rand`; GetTickCount deadlines compared unsigned with wrap.

## Oracle (the task of the oracle worker)

Write `tests/action_family_f6_runtime_original_oracle.py` plus a native scripted-host driver `tests/action_family_f6_runtime_oracle_driver.c`, copying the design of `tests/action_family_d1_runtime_original_oracle.py` / `..._oracle_driver.c` (and, where useful, `action_family_33_runtime_original_oracle.py`). Run the REAL dispatcher `0x427a50` with raw 0xf6 rows (real dependency tails through the real loader as the d1 oracle does) under Unicorn (`pip install unicorn` is done; the private game is at `work/original/GAME.EXE`, read-only).

Hooks (document them in the docstring): replaced `0x4c2790`, `0x4c2dfb`, `0x4e8d96`, `0x4fb77a`, `0x4fb2e3`, `0x4f6334`, GetTickCount, `0x50cd50` (scripted rand values), `0x423259` (scripted pointer into a scripted text arena, or 0), `0x448d11` (record the text); raising guards for the fatal paths. `0x4d39f9`, `0x4d3992`, `0x42ba3a` (and `0x423d33` for subtype 2), and every helper of the table above run as ORIGINAL code. Entry points driven directly with ECX = `0x61f4b1`: `0x45e1ca` (pointer), `0x45e587` (click, with `[0x5c39e5]` and the row phase set first), `0x45dd96`, `0x45dd4d`, `0x460f26` (render callback with the blits replaced by recorders; read their `ret N`; the callback also mutates +0x298, +0x29e and +0x2ac).

Compare per step: the ordered `F6_FX_*` effects with arguments (every rand, tick, sound and caption call), the packed object image against the original bytes (`f6_object_pack` mask), the generic Z entry bytes, the row phase and completion byte, `[0x5bb1ca]`, the scene-change cells, event flag table and `0x583999`, the pointer results (return value, `[0x5b44f0]`, `[0x5c39e5]`, sprite cell `0x5d1631`, `0x5d1639`, `0x5b44f4`, `0x5d162d`) and `f6_render_plan` against the recorded blits (kind, source rectangle, destination rectangle).

Scenarios: the 6 corpus bodies plus synthetic bodies (columns 1, 2, 10, 13; rows 1, 2, 3; deal count 0, 1, 5, more than the deck; mode byte 0, 2, 1, 255; bytes A, B, C 0/1; name lists with "NO SOUND" in all positions, all real, mixed; empty names; caption keys present, absent, short, 200 chars; sound flag words; slide parameters with steps 0..6 and interval 0, large; delivery / no-card animation counts 0, 1, 14 and zero or large intervals; scene blocks with 9999 and others, event flag index -1 and valid; start-flag word 1 and not 1; finish with each of `+0x2a8` / `+0x2a9`), each driven through phase 0, long runs of phase 1 with scripted ticks (before and after the deadlines, wrap past 2^32), scripted busy answers (0 and 1) and scripted rand streams (including values forcing the retry loops), pointer moves over cards, buttons, exit and outside in every state, clicks with candidates 0x27ec / 0x27ed / 0x27ef / other / -1 in every state, phase 2 with and without exit, subtypes 1 and 2, cleanup and re-init, invalidate with and without a slot, a false gate. Random scenarios with a fixed seed (at least 150). Drive each machine until the state machine reaches state 12 / phase 2 in a good share of the runs so that every case of the switch (states 1..12) is visited with real data.

Mutation check: at least 25 mutants of copies of `src/action_family_f6_runtime.c` (wrong state transition, swapped constants 300 / 500 / 1000 / 2000, wrong modulus operand, missing mark, wrong rect index or stride, skipped sound, skipped caption, win block applied on exit, cleanup that keeps the slot, wrong signed compare, off-by-one in a loop bound, ...), each must make the oracle report a mismatch. Report scenario, step, effect and mutant counts in `work/analysis/slices/RT-47.oracle-result.json` (private, local).

If the oracle shows the kernel differs from the original, you may fix `src/action_family_f6_runtime.c` minimally and list every fix (what the original does, evidence). Native safety differences are intentional: tag them in the oracle as expected differences and do not "fix" them.

## Rules

Edit/Write tools for source; shell only for builds and runs. Batch reads. No sleep polling. No rm, rm -rf or `git worktree remove` cleanups (the container is ephemeral). Stop and report at about 120 tool calls with what is done and what is missing. Do not commit, push or merge; do not call any `mcp__hearthbot__` tool. Keep new code portable C11 (`-Wall -Wextra -Wpedantic -Werror`).
