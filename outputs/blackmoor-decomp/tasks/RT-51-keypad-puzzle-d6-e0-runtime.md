# RT-51: raw 0xd6 and 0xe0 keypad puzzle runtime

Owner thread: Claude Sonnet (cloud). Follows RT-47 (PR 114) and RT-49 (PR 113). Ranking from `scene-action-coverage.json` after PR 114: 0xd0 is RT-50's; of the rest the handler `0x471722` serves two missing types at once (raw 0xe0: 3 rows in resources 1734 and 1737, raw 0xd6: 1 row in resource 2033) and has no helper beyond the engine's sound and surface calls, so it is the cheapest to close. The contract is `src/action_family_e0_runtime.h` (written first: the object map, the body map and the host callbacks are its comment; kernel, binding, app glue, tests and oracle all follow it). Disassembly helpers for the container are in `work/rt51/` (private, untracked): `pe.py` (`rd`, `dis`, `p`), `arms.py` (`flow`, dispatcher jump table), and the listings `handler_0x471722.asm`, `pointer_0x470ffe.asm`, `click_0x4712bd.asm`, `render_0x472a5c.asm`, `cleanup_0x470ddc.asm`, `reset_0x470d7a.asm`, `invalidate_0x470e31.asm`, `scene_reset_0x470e71.asm`, `loader_0x470e8e.asm`.

## The original (GAME.EXE SHA-256 afd337a2...5c45)

* Arms `0x42a2c0` (raw 0xd6, flag 0) and `0x42a2fc` (raw 0xe0, flag 1) of dispatcher `0x427a50`: gate `0x423f57(deps, 0)`, then `push flag; push row; mov ecx, 0x62387c; call 0x471722` (thiscall, `ret 8`). The object (3,594 bytes used) is one static singleton shared by both types. Loader arms `0x41050b` / `0x41053a` call `0x470e8e` (malloc and copy 1,733 / 294 bytes); parsers `src/action_family_d6.[ch]`, `src/action_family_e0.[ch]`.
* Handler `0x471722`: phase switch on the row phase dword (`0x5bb632 + row*0x8d`): phase 0 `0x471786`, phase 1 `0x471dbe` (state `obj+0xd2c`: 0 `0x471dde`, 1 `0x4723d6`, 2 nothing, 3 `0x472420`, 4 `0x47259f`; above 4 nothing), phase 2 `0x4726a3`. Pointer `0x470ffe` (call site `0x4f0e68` in the cascade `0x4f0059`), click `0x4712bd` (call site `0x43b2d7`), invalidate `0x470e31` (`0x43d99c`), cleanup `0x470ddc` (`0x43deb6` and the end of phase 2), scene reset `0x470e71` (`0x438494`, `0x4384e4`), render callback `0x472a5c` (generic Z entry of type 10; registered by phase 0).
* Strings (read from the exe, they are code labels): entry label `KEYPAD PUZZLE OVERLAYS` (`0x54c498`), surface labels `DF KeyPadPuzzle Surface` (`0x54c4b0`) and kind `CIFTREE` (`0x54c4c8`); the `NO SOUND` 9-byte compares at `0x54c480 0x54c48c 0x54c4d0 0x54c4dc 0x54c4e8`; blit labels `Keypad buttons down` / `Keypad buttons up refresh` / `Ordering puzzle pSrcSurface`.
* External calls (host callbacks of `E0Host`, one per original call, in the original order): `0x4d39f9` (slot), generic entry stores `0x5d1591..0x5d15b3` (type 10, callback `0x472a5c`, surface := `[obj+0xd24]`, flags 0/0/1/1, word 0, label), `0x4c2790(ECX 0x5cf659; "CIFTREE", body+0, 6, label)`, entry surface store `0x5d1599`, `0x4fb77a` / `0x4fba69` / `0x4fb2e3` (ECX `0x5c3a67`), `0x4f6334` (ECX `0x5cf1eb`), GetTickCount (`call [0x52a23c]`), `0x4c2dfb(ECX 0x5cf659, &obj+0xd24)`, `0x4d3992`, `0x42ba3a(row)`; render only: `0x4c5377` (ECX 0x5cf659, opaque from the background surface `[0x5d15e3]`) and `0x4c5d4b` (keyed). The raw 0xe0 layout code also calls the CRT floor `0x50e19e` and `__ftol` `0x50ce04` (the native uses `floor` and truncation, exact for these inputs).
* Original defects the native code must NOT reproduce (tag them as expected differences): (1) for raw 0xe0 the handler reads body bytes past the 294-byte allocation (`+0x24e` the blink byte, `+0x24f..` round records, and `+0x2ec` only on the sets path): heap garbage in the original; the oracle's malloc hook hands out ZEROED storage and the native body buffer is zero beyond the loaded length, so both sides read zeros; (2) the matched-code compare writes `record[N]` (index N, not the matched index) and the unordered compare writes `scratch[K]` (index K, not the matched index): `scratch[30]` is `record[0]`, `record[30]` would be the solved bytes; native bodies are validated so N <= 29 when code sets exist; (3) a code set among the first `set_count` that starts with a zero byte reads an uninitialised local (native validation rejects it); (4) cols == 0 divides by zero with keys present; N > 100 overruns the 100-entry rectangle arrays and the 100 lit bytes; K > 30 or ordered mode with N > 30 indexes past the 30-word typed/record arrays; key click with a hover index outside 0..99 (all rejected by `e0_validate_body` / `E0_ERR_BOUNDS`).
* Original quirks the native code MUST reproduce: the failed-scene block tests the dword global `0x5bb57b` (stale value) when neither assignment ran; phase 2 stores `[0x5d1a8f] := 0` (a copied leftover); the render callback sets `obj+0xd3b := 1` (waiting) when it draws the pressed exit button and draws the exit rectangle even when `+0x24` is 0; unsigned GetTickCount compares (`jbe` / `jb`); the exit-rectangle hit leaves `obj+0xd2a` unchanged while a miss stores -1.
