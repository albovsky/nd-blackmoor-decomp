Each assigned function must become:

1. One native C function in your batch's `src/original_methods_fl22<x>.c/.h` that follows the original's control flow and call/store order one to one, citing the original address (`0x...`) in a comment and in its name (`m<va>_<name>`). Host calls go through the `Fl18Host` convention (args[0] is the last pushed argument). Your own world struct (`Fl22<x>World`). Do not reproduce Win32/MFC behaviour; call the host for callees.
2. A direct test (`tests/fl22<x>_direct_test.c` + `tests/test_fl22<x>_direct.py`): whole-object checks, ordered host-call logs, call-time probes (snapshot named state at the moment of a host call so a store before a callee that reads it is caught), boundaries of every branch.
3. A Unicorn differential test (`tests/fl22<x>_differential_shim.c` + `tests/test_fl22<x>_differential.py`): original bytes from `work/original/GAME.EXE` vs the native function on the same random fixtures, with callee state snapshots as in FL-21. Every instruction of the function must be reached (cover each branch); report instruction coverage of the window.
4. The ledger acceptance entry, written to `tasks/fl22<x>-acceptances.json` (a JSON list shaped exactly like the FL-21 entries (see `tasks/fl21a-acceptances.json`) of `port_acceptances` in `function-ledger-overrides.json`: `class native_oracle_verified`, `native_source`, three `tests` pointers, `oracle` {path, window} where the window is the full function range of an oracle whose executed window covers the whole body, `parts_accounted []`, `note`, and `blockers_reviewed [{id, rationale}]` with a rationale of 40+ characters for each receipt blocker that the ledger lists for the function, saying what the receipt item covers and how the port handles it). Do NOT edit `function-ledger-overrides.json`, `function-ledger.json` or `function-evidence.json`; root merges the snippets and regenerates.

Find each function's oracle path/window and blocker ids with `python3 scripts/audit_port_candidates.py --va 0x...` and the function's `evidence` and `blockers` in `function-ledger.json`. Disassemble from `work/original/GAME.EXE` (capstone, `pip` `unicorn capstone pefile` are installed; Ghidra exports under `work/analysis`). Use the disassembly as the source of truth; do not trust names from older native code. Read the oracle's own use of the function if the receipt text leaves a doubt.

Keep tests proportional: direct + differential per function, no extra frameworks. Do not edit shared files (`test_fl_differential.py`, other batches' files) except to add a new optional parameter if strictly needed, and say so.
