# RT-39: raw 0x4b caption text row

Owner thread: Claude Sonnet (cloud). Follows RT-38. After PR 101, 2,019 of 2,078 scenes had every action type handled. Raw 0x4b (9 rows, 5 scenes) is the top of the remaining list in `scene-action-coverage.json` and unblocks all 5 (2,019 to 2,024). 0x1b (`0x414947`) and 0x7d (`0x4eb5f2`) were not folded in: they call different object methods and are their own slices.

## The original (GAME.EXE, SHA-256 afd337a2...5c45)

* Loader inline constructor `0x40c625..0x40caac` of `0x40b34a` (A-4B.1; `src/action_family_4b.c`): selector word -1 selects a 33-byte AUTOTEXT key (35-byte body), any other selector is an inline byte count (at most 9999). The object is the LE16 length word (text length + 3), the text and the marker `<e>`. A key row looks the key up with `0x423259` on the table `0x619a6b`; a missing key makes the loader `sprintf` the string `Game Error (please contact Tech Support) missing auto text: %s<n>` (`0x53f398`) and use that as the text (record 2804/0 of the corpus does). A table value above `0x9c40` bytes is fatal (`0x40c6f7`); the native construct rejects anything above 32,761 bytes, which covers it.
* Dispatcher `0x427a50`, arm `0x42816e..0x4281ce`, gate mode 0 (`0x423f57(deps, 0)`, the executor's default). For a true gate the arm calls the caption writer `0x448d11` as a thiscall on the text box `0x619a05` with four stack arguments: the caption surface `[0x5d03b3]`, the text pointer (the row object + 2, past the length word), writer mode -1 (caption), measure 0 (`ret 0x10`, the return value is unused), then `0x42ba3a(row)`, the generic completion: subtype 1 sets the completion byte, subtype 2 resets the dependencies (`0x423d33`) and leaves the row open, the phase word is cleared. A false gate does nothing.
* Corpus (decoded scene resources): 5 scenes, 9 rows, all key rows, all subtype 1, 8 with dependency tails, 1 key missing from the AUTOTEXT table (the original error string).

## Native implementation

`src/session_bindings_a4b.[ch]`: one binding. `session_a4b_begin_scene` builds the object of every 0x4b row of the scene (decode and `action_family_4b_construct` from A-4B.1, AUTOTEXT through the host lookup, the missing-key string with the format raw 0x51 uses), once per scene. `session_a4b_handler` hands the object text (including `<e>`) and its length word to the host `write_caption`, then returns COMPLETED with phase 0 so the executor applies the generic completion by subtype. Host callbacks: `lookup` (`ActionFamily51AutoTextLookup`; REQUIRED for key rows, a missing hook leaves those rows UNSUPPORTED, inline rows still run) and `write_caption` (REQUIRED; UNSUPPORTED when no caption renderer is bound: the row is untouched; ERROR when the writer fails). Registration `bindings[35]` in `src/blackmoor_app.mm` (count 36; slot 33 is raw 0x2d, RT-36), the module pair added to `scripts/build_native_app.sh`, `scripts/build_action_family_4b_runtime.sh`. In the app the writer is raw 0x51's `native_a51_write_caption` (the same text box and caption surface) and the lookup is `native_a51_autotext_lookup`.

## Verification

* `tests/action_family_4b_runtime_test.c`: 3 unit cases (loader objects, handler effects and status mapping, AUTOTEXT lookup variants) on a synthetic scene (ASan/UBSan clean); `tests/test_action_family_4b_runtime.py` runs them plainly, under sanitizers and under 11 source mutants (the host-status mapping and lookup rules the oracle cannot reach).
* `tests/action_family_4b_runtime_original_oracle.py` (+ `_oracle_driver.c`): the real dispatcher `0x427a50` runs the rows under Unicorn against the native binding. Objects come from the real original loader (the A-4B.1 machine with the original AUTOTEXT table) and are compared with the native binding's objects byte for byte (length word and text); then the arm runs: which rows entered the arm, the caption writer calls (row, `this`, surface, mode, measure, length word, every text byte) against the native host's writes in order, the generic completion `0x42ba3a` once per visited row, the dependency reset `0x423d33` exactly for the rows the native disposition resets, the completion byte and phase of every row, unvisited rows unchanged. 96 scenarios (the 9 real rows plain, gated and under every subtype; inline texts of every shape up to 9999 bytes; keys found in either case, absent, padded with junk, 32 characters wide, a 32,761-byte value; subtypes 0, 1, 2, 3, 4, 255 with phases set; event gates; world mode 4; tails; 60 random), 1,074 visits, 549 loader objects compared (99 of them the missing-key string), 0 mismatches, 19 of 19 native mutants caught. The result JSON is private (`work/analysis/slices/RT-39.oracle-result.json`).
* `tests/action_family_4b_runtime_corpus.c`: all 9 corpus rows through the binding with the decoded AUTOTEXT resource. `tests/action_family_4b_runtime_executor.c`: the production executor drives synthetic rows (a gated row, a subtype 2 row that writes every tick) with the real binding; two executor mutants caught.

## Limits

* The macOS glue (`blackmoor_app.mm`) is not compiled or run in the cloud.
* The caption writer `0x448d11` is replaced in the oracle (its arguments and text are compared); the writer itself has its own oracle (S05-1). The oracle builds the rows in memory (the scene loader `0x40b34a` is not run); the dependency tails of the corpus rows are replayed behind stand-in event records.
* Native safety differences from the original: a resolved AUTOTEXT value above 32,761 bytes (the original allows 40,000) and an unterminated key are rejected at scene load; a host without a caption renderer leaves the row untouched (UNSUPPORTED) instead of drawing.
* The debug flag `0x63a4cd` is modelled as 0 (with it set the original logs the missing key before the fallback).
