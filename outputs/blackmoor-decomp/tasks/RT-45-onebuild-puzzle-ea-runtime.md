# RT-45: raw 0xea Onebuild (jigsaw) puzzle runtime

Owner thread: Claude Sonnet (cloud). Follows RT-35 (Turning Puzzle 0xd1, `tasks/RT-35-turning-puzzle-d1-runtime.md`) and RT-24 (Mouselight 0xd9) and copies their pattern. Raw 0xea is in 6 rows of 3 scenes (2282, 2283, 2284; actions 15 and 16 of each; all subtype 1, two dependency rows): the 20-piece jigsaw `JAN_JigsawPUZ_OV`. In every one of them it is the only type without a handler. Body decoder: `src/action_family_ea.[ch]` (A-EA.1, fixed 3,847 bytes).

## The original (GAME.EXE, SHA-256 afd337a2...5c45)

Recovered by this slice (Ghidra pseudocode is navigation, the numbers below were read from `asm/FUN_*.s` and the oracle re-checks them):

* Dispatcher `0x427a50` arm `0xea` at `0x42a759`: gate `0x423f57(deps, 0)`, then `0x4867bd(ECX = 0x6252ad, row)` (the row is the word argument). The object is a static singleton of `0xc3b` bytes (`0x6252ad..0x625ee8`, power-on constructor `0x483efa` -> `0x483f6a`).
* Handler `0x4867bd`, a switch on the row phase dword (`0x5bb632 + row * 0x8d`):
  * **phase 0**: row, active `+0xba7 := 1`, `[0x5bb1ca] := 1`, `0x4e8d96`, hand/drag/flag/state resets, rectangle blocks zeroed (`+0xaa0..+0xadf`, `+0xbb1..+0xbc0`), animation cell size (`+0xc37/+0xc39`), the piece source image `0x4c2790("CIFTREE", name, 6, "DF Piece Source Surface")` only when `+0x22 == 0`, the optional Multi_Anim image (animation area has height and the name is neither `NO_FILE` nor empty), the 20x4 entry surface table zeroed, then `0x48421e(i)` for every piece, then `0x4d39f9` (Z slot), the Z entry stores (type 10, callback `0x4876ed`, label `ONEBUILD PUZZLE OVERLAYS`), row phase := 1.
  * **piece init `0x48421e`**: rect D (loose pieces) or rect C (flag byte `+0x41`) becomes the piece rectangle (translated by the view origin `0x583186/0x58318a` through `0x4841cb`); entry 0 is a new DF surface (`0x4c2a8d`) filled by `0x4c51a5` from the source image (rect B when it has width and height, else rect A, which also sets piece byte `+0x84`); with rotation allowed (`body+0x24`) or a non-zero start orientation, entries 1..3 are copies rotated by `0x4c7070` (width and height swap), or 0 when the piece flag byte is set.
  * **phase 1**: a seven-state machine on `+0xbac`: 0 idle (acts only when `+0xc2b` was set by the exit-area click: solved check `0x486725`, then sound/wait or the animation), 1 wait out the pick/drop sound then decide good drop (`0x48633c`) / bad drop (`0x485fb6`, when the moving rect leaves the area rect `0x4866b4`), 2 wait out the feedback sound and clear the caption, 3 animation step (grid cell math), 4 timed wait, 5 wait for the win sound (row phase := 2), 6 done: win sound and caption.
  * **phase 2**: `[0x5bb1ca] := 1`; the win block (`body+0xdab`, applied when done and not exited) or the exit block (`+0xede`): scene-change cells plus start flag plus engine mode 4 unless the scene word is 9999, event flag store unless the index is -1; then `0x42ba3a(row)` and the clear `0x483fb5` (surfaces, slot, `0x483f6a`).
* Pointer receiver `0x484f42(x, y, rect)` (cascade `0x4f0059` at `0x4f0d61`, x = `[ptr+0x5e]`, y = `[ptr+0x5a]`, rect = `ptr+0x4a`): while dragging it advances the moving rectangle (`0x484d87`, `0x484caf` clamp) and picks the good/bad drop candidate (`0x277b` / `0x277a`); otherwise it builds the two hit lists and writes the candidate and cursor (`0x4854fb`): `0x2778` rotate zone, `0x2777` unplaced piece, `0x277c` animation/exit area, `0x2779` exit button.
* Accepted-release chain `0x43b327` -> `0x48569e` (candidate `[0x5c39e5]`); second-button event `0x43c11f` -> `0x484ac0` (rotates the top unplaced or the held piece); `0x4840d9` invalidate (`0x43d9ec`); `0x483fb5` clear (`0x438c3e`, `0x43df15`); render callback `0x4876ed`.
