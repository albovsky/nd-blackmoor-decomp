# A-28.2: Normalized RGB blending

Prove the original x87 blend table and packed pixel values.

Parent: A-28. Read its packet and PROJECT-SPEC.md. Root owns this child and shared integration. Child evidence does not complete the parent while another child remains unresolved. Use immutable original code and installed assets; enumerate hooks and exclusions. No GUI while the Mac is locked.

Status: bounded blend kernels complete for explicit x87 modes; production precision policy remains unresolved.

Evidence: the original LUT window and actual packed pixel routine at `0x4477d1` were executed under forced CW `0x037f` and `0x027f`. The native kernel matched 24 sampled LUT weights per mode (196,608 entries total) and 24 packed-pixel weights per mode (288 visible pixels total) with zero mismatches. The fixture uses a 3x2 RGB565 output with a 4-pixel source pitch. The DirectDraw presentation/upload and final engine pump are stubbed only after the original pixel writes. See `work/analysis/slices/A-28-original-oracle.json`.

The near-boundary probes show 838, 723, 462, and 512 LUT entry differences between the two modes at weights adjacent to 0.5 and 0.25; exact 0.5 and 0.25 match. A naive binary64 expression also differs from original CW `0x037f` at these same near-boundary probes. CRT/startup tracing did not establish which precision field the game leaves active at the controller, so the API exposes both CW modes and callers must provide a proven mode before live rendering.
