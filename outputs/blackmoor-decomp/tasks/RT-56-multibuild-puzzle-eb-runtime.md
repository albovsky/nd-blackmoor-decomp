# RT-56: raw 0xeb Multibuild puzzle runtime

Owner thread: Claude Sonnet (cloud). Follows RT-54 (PR 119, 0xe4) and RT-45 (0xea Onebuild, the closest sibling: same piece/entry/Z-slot design). Raw 0xeb is the "Multibuild Puzzle" (resources 1600 action 6 and 2305 action 0, subtype 1, 2,612-byte body decoded by `src/action_family_eb.[ch]`). It is one of the last blockers (2 scenes). Pieces of up to 20 types are dragged from the bin onto an area; a type flagged "spawns copies" leaves a copy behind (up to 80 instances); the placed counters per type must match the required counts; rotation by click zone or second mouse button.

Contract: `src/action_family_eb_runtime.h` (written first by the owner thread from the Ghidra pseudocode and the disassembly); the kernel `src/action_family_eb_runtime.c` is the owner thread's. GAME.EXE SHA-256 afd337a2...5c45; private evidence is `work/original/GAME.EXE` (already extracted at `/home/user/nd-blackmoor-decomp/work`); disassembly helper `work/rt56/pe.py` (`python3 pe.py <hex va> <len>`), Ghidra pseudocode of every function `python3 work/rt56/pseudo.py <hex va>...` (saved copies of the class in `work/rt56/ps/<va>.c`), per-function annotated assembly `asm/FUN_<va>.s`. The two real 2,612-byte bodies are in `work/analysis/hiff-resources/1600.bin` and `2305.bin` (locate by the record in `work/analysis/slices/A-EB.1.corpus.json`). `unicorn` and `capstone` are installed (pip, already done).

Unlike 0xea there is no `_rand`.

Process cells: start flag `0x5bb1ca`; current scene `0x5bb57b` (read for the saved-state compare, written by a finish block); saved puzzle state `0x5a055d` flag (dword), `0x5a0561` scene (word, also written by the class at `0x47a416`), `0x5a0563` 20 counter bytes, `0x5a0577` the 80 instances (0xb90 bytes), `0x5a1107` count, `0x5a1109` total; scene-change cells `0x5bb57b 0x5bb599 0x5bb595 0x5c39ff 0x5bb59b 0x5bb59f 0x5bb5a3`, engine mode `0x583999 := 4`, event flags `[0x585801 + 4 * i]`, cursor cells `0x5b44f0 / 0x5b44f4`, `0x5d162d 0x5d1631 0x5d1639`, candidate `0x5c39e5`, generic Z entry table at `0x5d1591` (0x4a bytes each; entry surface `0x5d15e3`), view rect `0x583186` and clip rect `0x583196..0x5831a2`, debug flag `0x63a4cd` (0), empty-string global `0x63a89c`.

Handler phases (row phase dword `0x5bb632 + row * 0x8d`): phase 0 = init, phase 1 = switch on obj+0x13ca (states 0..6; 2 does nothing), phase 2 = finish (start flag, stop sounds, win or exit scene block, `0x42ba3a(obj row)`, then cleanup `0x47e2a5`). The header and the kernel carry every detail; where this packet and the disassembly disagree the disassembly wins and the packet gets fixed.

Known wrinkles preserved in the kernel (do not "fix"): the saved-state compare in the piece builder runs after the handler overwrote the saved scene (with the persist byte set, a saved flag and a different scene the records stay zero); the lists under the pointer are 20 words each; counters are indexed by instance in the overlap check of `0x47f421` (`obj[0x7a0 + j]`); the moving rect's right and bottom are left + w and top + h; a stale candidate with an empty list indexes piece -1 in the original.

Native-only refusals (the oracle must not run them against the original; test them natively): body validation (`eb_validate_body`: type count outside 0..20, piece size outside 1..4096, unterminated fields, animation area with zero columns), phase 1/2 without phase 0, hand or list index outside the instances, instance type byte outside 0..19, more than 20 pieces under the pointer, event flag index outside the host window, spawning a 81st instance, captions longer than the 204-byte (click) or 208-byte (win) local, the z-level render loop guard of 0x4000.
