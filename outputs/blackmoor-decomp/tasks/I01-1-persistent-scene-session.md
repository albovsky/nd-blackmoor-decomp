## Session architecture and invariants

1. Keep process/game world, ActionUI controls/phone rows, audio channels, caption state and owned pixel surfaces persistent. Keep an executor for each loaded scene. Payload copies and mutable action state live for the scene; callbacks borrow only objects that outlive the executor. Destroy the executor before the borrowed scene/world/provider objects. Define shutdown and reset ownership explicitly.
2. Route update() by explicit startup versus scene mode. A scene tick advances media using the session clock, refreshes authoritative conditions, applies accepted input, calls scene_executor_step_frame in recovered order, and composites/presents the resulting surfaces. Clear pointer edges only after their correct consumer has received them. The app and offscreen fixtures use this same path.
3. Source real logical pointer coordinates from platform events. Apply BOOT viewport-origin subtraction, scroll and cursor hot-point offsets from recovered state. Recover cursor-context/modal guards and WM_LBUTTONUP acceptance. Preserve the executor's prior candidate consumption before dispatch and current candidate scan after dispatch. Exercise actual resource rectangles; never activate the first hotspot directly or manufacture phase 2. Retain A-62 selector/control state across ticks and connect its verified interaction path with a source-backed upstream provider.
4. Use persistent native audio in output mode for live operation and the same session with an injected clock/offline audio host in automated tests. Poll completion normally; a live tick must not drain the entire sound or block until completion. Bind sound-control only after accepted S04-1 review; unimplemented controls/fades/pan remain explicit. Track scene/channel generations so an old completion cannot trigger a transition in a new scene. Preserve original stop/unload/completion order.
5. Bind reviewed caption layout/lifecycle to owned offscreen surfaces and native composition, sharing authoritative A-51/global flags. A diagnostic recorder cannot return successful presentation in the runtime. Preserve renderer callback side effects and source order; keep unsupported presentation explicit until the provider is accepted. Respect wait-mode-0 noncompletion and recovered dismissal owners. Report enabled and disabled caption paths separately.
6. Preserve the whole SceneTransitionRequest, including three opaque words and three opaque dwords. Recover their semantics on the exercised routes before consuming them; copying only target_scene is insufficient. Stage prospective resource/media/executor ownership and preserve source/target frames for A-28. Pin original scene-clear, visit-increment, clock and resource call order; distinguish fatal original load failures from any deliberate native host recovery. A failed target load must not leave dangling callbacks or falsely mark a successful visit. Never claim transaction rollback equivalence if original world effects have already occurred.
7. Refresh condition views from the same authoritative event-flag storage/count as ActionCoreWorld, inventory selection/presence, visit counts and clock values. Earlier ACT-row changes must affect later rows in the same pass. Opcode 3/4/5 providers must come from recovered actual producers; zero-filled placeholders are errors when required by an eligible gate. Keep unsupported action/opcode/provider reporting exact and stop at the first unresolved eligible row without skipping it.
8. Use one clock domain per session, with explicit scripted time in tests. Preserve source GetTickCount ordering and DWORD wrap for A-64 and timer providers. Keep native Bink timestamp adaptation and proprietary codec/timing parity limits explicit. A-28 uses reviewed full-canvas capture and semantic PC53 normalization with raw-original CW evidence; retain composition/capture/pump/source-order boundaries. Do not recursively reenter media/dispatch while pumping an effect.
