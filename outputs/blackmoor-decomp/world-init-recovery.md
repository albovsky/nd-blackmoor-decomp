# Original New Game world-initialization contract

Scope: read-only recovery from original work/original/GAME.EXE (PE32/i386, SHA-256 afd337a2468e0cd540f487db2c121ccb9ccb9757836578c15d2d8a52f3485c45). This is a partial contract for state touched by the full initializer, not a complete inventory of every global it or its callees affect. The pseudocode exports are explicitly unverified decompilation; loop widths and the inventory stride below are checked against original x86 instructions.

## New Game reaches the initializer later

At VA 0x4da430, menu dispatch DAT_005aff55 == 1 (logged as “user selected NEW GAME”) runs when DAT_005aff4d == 3. If DAT_005e32b9 == 0, it sets DAT_005bb1e2=1, DAT_00583981=14, DAT_00583999=0, and clears 33 bytes at 0x0063a565. It calls VA 0x43dbd5, which only sets pending latch DAT_005bb1c4=1. The primary loop dispatches state 14 to VA 0x438150; state 0 there calls full initializer VA 0x4381f4. The menu callback schedules the reset; it does not perform it synchronously. When DAT_005e32b9 != 0, this case instead selects state 17, clears DAT_00616783 and DAT_005e32b9, and does not select the state-14 full-init path.

## Boot inputs and reset boundaries

The initial scene/coordinates are selected from globals populated before this routine. If DAT_005bb1de==0, the ordinary start tuple is (scene=0x5b01f0, coordA=0x5b01f2, coordB=0x5b01f4) unless either test-override flag 0x63a4d1 or 0x63a4d5 is nonzero; then scene comes from 0x63a4dd and is copied to 0x63a4ed, while coordinates remain from the ordinary tuple. If DAT_005bb1de!=0, the alternate tuple is (scene=0x5b01fe, coordA=0x5b0200, coordB=0x5b0202). The selected tuple populates current-scene/location globals 0x5bb57b, 0x5bb593, 0x5bb597. DAT_0063a4d9 enables additional test-mode handling. The decoded current boot resource reports initial_scene=0; whether that field directly maps to 0x5b01f0 is not demonstrated here, and actual runtime values of the config globals remain unresolved.

On cold process launch, event-flag base 0x585801 is in the PE .data virtual zero-fill tail: .data starts at VA 0x537000, virtual size 0x10713c, raw size 0x33000. This supports zero initial BSS at cold launch, but does not prove that a later in-process New Game clears lower event IDs. VA 0x4381f4 explicitly clears only the upper segment listed above. Normal scene clear at 0x43dbe3 clears 31 dwords at 0x5867a1 (IDs 1000..1030), not the full segment; it resets scene timer fields only when not restoring and leaves run elapsed field alone. Successful scene loads increment visit counts as described above. Save/restore routines copy observed table extents but do not establish event-table semantic capacity.

## Unresolved / safe implementation boundary

- Do not use 4,096 as original event-flag capacity: that is an analysis-model choice. Logical/allocation maximum is unknown; the direct clear proves only IDs 1000..2250, and corpus use proves a minimum of 2,243 slots. Keep lower-ID behavior on same-process New Game explicitly unresolved until its other initialization paths are traced.
- The 30 dwords at 0x5839b1, auxiliary table beginning 0x583a29, and other serialized records have exact observed reset/copy spans where stated but incomplete semantics/capacity contracts.
- A narrow future oracle candidate is VA 0x44aff2: no arguments, just 30-short and 10-float sentinel stores. Do not call full VA 0x4381f4 as an oracle substitute: it depends on tick count, resources, GUI/global state, configuration, and many callees. This pass did not execute original binary.

Correction note: an earlier draft labeled the float bit pattern 0x461c3c00 as 10000.0f. Direct original execution and IEEE-754 decoding establish that it is 9999.0f.
